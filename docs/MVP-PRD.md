# My Growth OS：第一版 MVP 产品设计

## 1. 产品定位

My Growth OS 是一个面向个人使用的成长管理 Web App，第一版聚焦于：

> 目标管理 → 灵活排程 → 学习记录 → 每日复盘 → 作品沉淀

它不是单纯的 Todo List，而是把考研、英语、论文、技能学习和 GitHub 作品集放在同一个可持续执行的系统中。

第一版采用响应式 Web 设计，后续可扩展为 PWA 或移动端应用。

## 2. 当前用户目标

路线并列推进，但优先级为：

1. 考研
2. 实习
3. 保研
4. 留学（香港、英国、德国，作为保障路线）

主要学习方向：

- 雅思 7.0+
- 北大软微金融科技：英语一、数学二、831 经济学综合
- 北大经济学院金融：英语二、数学三、431 金融学综合
- 金融科技、绿色金融、AI+金融、数据分析
- Python、Excel、SQL 和金融数据分析作品集
- 一篇可投稿论文，作为科研能力证明

## 2.1 初始时间参数

- 起床时间：07:00
- 睡觉时间：23:30—00:00（按用户输入暂定）
- 每晚计划确认时间：23:00
- 正常日学习目标：3—4 小时
- 冲刺日学习上限：5—6 小时

排程器默认以正常日目标生成计划；只有在用户主动确认或临近重要截止日期时，才建议使用冲刺日强度。即使是冲刺日，也必须保留休息、运动和突发事件缓冲。

### 3.1 首页总览

首页展示：

- 今日日期和今日计划
- 明日计划确认状态
- 各路线进度
- 今日学习时长
- 即将到期的任务
- 最近完成的项目、论文或 GitHub 作品

### 3.2 课程与排程

课表用于生成可用时间窗口，但不直接决定所有学习内容。

#### 硬性占用时间

以下三门课的上课时间不可安排其他学习任务：

- 财政学
- 金融科技
- 应用随机过程

#### 可学习时间

其他课程的上课时间默认视为可学习时段。用户明确表示这些课程不听课，因此可以在对应时间安排其他任务。

适合安排的任务包括：

- 背单词
- 听力训练
- 雅思阅读
- 网课学习
- 轻量笔记整理
- 编程练习

#### 课程元数据

即使不作为听课时间，其他课程仍保留以下信息：

- 课程名称
- 周次
- 上课时间
- 教室
- 是否有考试
- 是否有作业
- 是否有考勤要求

这些信息只用于提醒和截止日期管理，默认不阻塞学习排程。

当前学期课表已按“星期 + 周次 + 节次”结构化。原始 PDF 没有提供每一节对应的具体钟点，因此第一版先使用节次作为排程坐标；补充学校的节次时间表后，再转换为具体分钟范围。

### 3.3 每日计划

每日计划必须经过“候选 → 确认 → 执行 → 复盘”四个状态。

```
系统读取课表和截止日期
        ↓
生成第二天候选计划
        ↓
用户晚上确认任务量
        ↓
计划正式生效
        ↓
次日记录完成情况
        ↓
自动生成每日总结
```

计划生成原则：

- 先排固定听课时间，再排学习任务。
- 只使用预计可用时间的 60%—70%。
- 保留休息、运动、突发事件和补漏空间。
- 任务未完成时默认顺延或重新排序，不直接判定为失败。
- 任务量由用户每晚确认，系统不能擅自大幅增加。

### 3.4 Todo、番茄钟与学习记录

每条任务至少包含：

- 标题
- 所属路线
- 所属目标
- 预计时长
- 优先级
- 截止日期
- 状态
- 是否可在课堂自习时完成
- 实际学习时长
- 关联成果

学习记录可关联：

- 雅思练习
- 数学章节和错题
- 论文文献或写作进度
- Python / Excel / SQL 项目
- GitHub 资源学习

### 3.5 目标与路线

考研目标必须拆成两条独立 Track，不能把数学、英语和专业课混为一条：

```
北大软微金融科技
├── 英语一
├── 数学二
└── 831 经济学综合

北大经济学院金融
├── 英语二
├── 数学三
└── 431 金融学综合
```

其他路线：

- 雅思
- 论文科研
- 实习
- 保研
- 留学
- 技能与作品集

## 5. 排程器不变量

以下规则是系统必须始终保持的核心行为：

1. 任何任务不能与财政学、金融科技、应用随机过程的硬性时间重叠。
2. 其他课程时间可以被安排学习任务。
3. 每日计划在用户确认前只能是候选状态。
4. 计划必须使用统一的时区、日期和分钟单位。
5. 周次和跨周任务不能因为日期切换而丢失。
6. 任务延期必须保留原始计划、延期原因和新计划时间。
7. 用户临时插入事件后，系统只能重排受影响的任务。
8. 个人笔记、健康记录和生理期数据默认不公开到 GitHub。
9. GitHub 资源必须记录来源和许可证，不能默认复制第三方内容。
10. AI 可以提出计划和解析自然语言，但跨模块重大变更必须等待用户确认。

## 7. Agent 设计（第一版只做逻辑角色）

第一版不拆成多个独立服务，而是在一个应用中定义角色和权限：

- 总管 Agent：读取全局状态，生成每日计划和冲突提醒。
- 考研 Agent：维护数学、英语、431、831 任务。
- 英语 Agent：维护雅思、六级、考研英语和经济学人任务。
- 论文 Agent：维护选题、文献、方法和写作阶段。
- 技能 Agent：维护 Python、Excel、SQL 和作品集项目。
- GitHub 资源 Agent：整理收藏项目、许可证和复用方式。

总管 Agent 是唯一可以修改跨模块计划的角色；健康数据、论文结论、GitHub 修改和外部发布等操作必须先获得用户确认。

### 第 3 阶段：成长模块

- 考研双 Track

### 第 4 阶段：智能化与扩展

- 自然语言记录进度
- Agent 协作
- 新闻和外刊推送
- 健康记录
- PWA 和移动端适配

## 9. MVP 验收标准

第一版完成后，用户应当能够：

1. 看到当天和第二天的课程与任务。
2. 确认三门固定听课课程不会被安排其他任务。
3. 在其他课程时间安排学习任务。
4. 每晚调整第二天任务量并确认计划。
5. 使用番茄钟记录学习时长。
6. 查看每日和每周学习统计。
7. 分别管理数学二、数学三、431 和 831。
8. 保存 GitHub 项目、许可证和学习笔记。
9. 将论文和数据分析项目沉淀为作品集条目。
10. 在突发事件后重新安排受影响任务，而不是丢失记录。
